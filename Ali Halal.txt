# Ali Halal Restaurant Digital Menu System Requirements Document

## 1. System Overview

### 1.1 System Name
Ali Halal Restaurant Digital Menu System

### 1.2 System Description
A full-stack digital menu and order management system for Ali Halal Restaurant. Customers scan QR codes to access the menu, place orders, and make payments via their mobile devices. Restaurant administrators manage orders in real-time, set food preparation times, and send serving notifications - streamlining the entire dine-in experience.

### 1.3 Technology Stack
- **Front-end**: React.js\n- **Back-end**: Node.js with Express.js
- **Database**: MongoDB
- **Architecture**: MERN Stack (MongoDB, Express.js, React.js, Node.js)
- **Additional Tools**: Mongoose for MongoDB object modeling, JWT for authentication, Socket.io for real-time updates\n
### 1.4 Core Features
- Customer login with phone number and table verification
- QR code scanning access to digital menu
- Categorized menu display with multiple cuisines
- Shopping cart and order placement
- Online payment and cash payment options
- Real-time order display on admin dashboard
- Admin order management with preparation time settings
- Automated serving notifications to customers
- Restaurant and food review system
- Responsive design for mobile and desktop devices

### 1.5 System Access Points
- **Customer Side**: Access via QR code scanning (e.g., http://192.168.x.x:3000)\n- **Admin Side**: Access via dedicated admin URL (e.g., http://192.168.x.x:3000/admin) with secure login authentication

## 3. Admin-Side Features

### 3.1 Admin Access\n- **Admin URL**: http://192.168.x.x:3000/admin\n- Secure admin login page with username and password
- Session management for admin access control
- Desktop-optimized interface for restaurant staff

### 3.2 Real-Time Order Dashboard
- Display all incoming orders in real-time
- Order details: order ID, table number, customer phone, items ordered, quantities, total amount, payment method, order time
- Order status indicators: New Order, Preparing, Ready to Serve, Completed\n\n### 3.3 Order Management
- **Accept Order**: Admin confirms new orders and changes status to Preparing
- **Set Preparation Time**: Input estimated cooking time (e.g., 15 minutes, 20 minutes)
- **Mark as Ready**: Change status to Ready to Serve when food is prepared
- **Send Serving Notification**: Automatically notify customer via system notification when order is ready
- **Complete Order**: Mark order as completed after serving

### 3.4 Timing Notifications
- Visual and audio alerts for new orders
- Countdown timer showing remaining preparation time for each order
- Automatic notification trigger when preparation time is reached

### 3.5 Menu Management (Optional)
- Add, edit, or remove menu items
- Update prices and availability status
- Manage menu categories\n\n### 3.6 Order History & Reports
- View completed orders by date range
- Sales summary and revenue reports
- Customer feedback and review history

```javascript
{
  _id: ObjectId,

  createdAt: Date (default: Date.now),
```

### 4.2 tables Collection
```javascript
{\n  _id: ObjectId,
  tableNumber: String (required, unique),
  isOccupied: Boolean (default: false),

  updatedAt: Date
}
```

### 4.3 menuCategories Collection
```javascript
{
  _id: ObjectId,
  categoryName: String (required),
  displayOrder: Number\n}
```

### 4.4 menuItems Collection
```javascript
{
  _id: ObjectId,
  categoryId: ObjectId (ref: menuCategories),
  itemName: String (required),
  description: String,
  price: Number (required),
  isAvailable: Boolean (default: true),\n  createdAt: Date\n}
```

### 4.5 orders Collection
```javascript
{
  _id: ObjectId,\n  customerId: ObjectId (ref: customers),
  tableNumber: String (required),
  orderStatus: String (enum: [pending, preparing, ready, completed, cancelled]),
  totalAmount: Number (required),
  paymentMethod: String (enum: [online, cash]),
  preparationTime: Number (in minutes),
  estimatedReadyTime: Date,
  createdAt: Date (default: Date.now),
  updatedAt: Date
}
```

### 4.6 orderItems Collection
```javascript
{\n  _id: ObjectId,
  orderId: ObjectId (ref: orders),
  itemId: ObjectId (ref: menuItems),

  itemPrice: Number (required),
  subtotal: Number (required)\n}
```

### 4.7 payments Collection
```javascript
{
  _id: ObjectId,\n  orderId: ObjectId (ref: orders),
  paymentMethod: String (enum: [credit_card, debit_card, digital_wallet, cash]),
  paymentAmount: Number (required),
  paymentStatus: String (enum: [pending, completed, failed]),\n  transactionId: String,

```

### 4.8 reviews Collection
```javascript
{
  _id: ObjectId,
  customerId: ObjectId (ref: customers),
  orderId: ObjectId (ref: orders),
```

```javascript
{
  _id: ObjectId,
```

## 5. Technical Implementation Notes

### 5.1 Front-End (React.js)
- Component-based architecture with functional components and React Hooks
- React Router for client-side routing
- State management using React Context API or Redux
- Axios for HTTP requests to backend API
- Real-time updates using Socket.io client
- Responsive design with CSS modules or styled-components

### 5.2 Back-End (Node.js with Express.js)
- RESTful API architecture
- Express.js framework for routing and middleware
- Mongoose ODM for MongoDB data modeling
- JWT (JSON Web Tokens) for authentication and authorization
- Bcrypt for password hashing
- Socket.io for real-time bidirectional communication
- CORS middleware for cross-origin requests
- Express-validator for input validation
- Route separation: customer routes (/) and admin routes (/admin)

### 5.3 Database (MongoDB)
- Mongoose schema definitions with validation
- Indexing on frequently queried fields (phoneNumber, tableNumber, orderId)
- Population for referenced documents
- Transaction support for order and payment operations
- Connection pooling for efficient database access

### 5.4 Real-Time Communication
- Socket.io for WebSocket connections
- Event-driven architecture for order updates
- Room-based communication for table-specific notifications
- Admin dashboard receives all order events\n- Customer receives notifications for their specific orders

### 5.5 Authentication & Security
- JWT-based authentication for admin users
- Password hashing with bcrypt (salt rounds: 10)
- Protected routes with authentication middleware
- Input sanitization to prevent NoSQL injection
- HTTPS for secure data transmission in production

## 6. Design Style\n
**Customer Side:**
- **Color Scheme**: Warm golden yellow (#F4A300) as primary color with deep red (#C8102E) accents for call-to-action elements; white (#FFFFFF) background for clean readability; light gray (#F5F5F5) for section dividers
- **Layout**: Card-based grid layout for menu items; sticky category navigation tabs at top; floating shopping cart icon with item count badge in bottom-right corner
- **Visual Details**: Rounded corners (8px radius) on cards and buttons; subtle box shadows (0 2px 8px rgba(0,0,0,0.1)) for depth; line-art style icons for food categories; prominent Add to Cart buttons in golden yellow with hover effect
- **Typography**: Sans-serif font family (e.g., Roboto or Open Sans); dish names in bold 18px; descriptions in regular 14px with 1.5 line height; prices in bold 16px with red color for emphasis

**Admin Side:**
- **Color Scheme**: Professional dark navy (#1A2332) header with white text; light background (#F8F9FA) for main content area; status color coding (green for ready, orange for preparing, blue for new orders)\n- **Layout**: Table-based layout for order list with sortable columns; sidebar navigation for different admin sections; fixed header with logout button\n- **Visual Details**: Minimalist design with clear data hierarchy; action buttons with icon labels; real-time update indicators with subtle animations; modal dialogs for order details
- **Typography**: System font stack for optimal readability; order IDs in monospace font; status badges with bold uppercase text
